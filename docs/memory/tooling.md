The spec lives in the private `second-brain` repo; this repo adopted it on 2026-10-19 and the rules below are now in force here. **How to apply**: a change to one of them is a change to the spec first, then pasted here — never the reverse.

- **Scaffold**: `CLAUDE.md` states the repository's visibility (public, measured 2026-10-19) so a Registry block never carries a `Last point:` or an open box; the commit template names no `Co-Authored-By` spelling of its own — the trailer is whatever the harness asks for (K2); `.claude/commands/memorize.md` is the canonical text (K6), which pushes from a cloud session and never from a local one; `AGENTS.md` is a symlink to `CLAUDE.md` (K1). Trap fixed on the way: `tsconfig.json`'s `include` carried `/tmp/nbuild/types/**/*.ts`, a path a build with a moved `distDir` once wrote; Next rewrites that list on its own, so an absolute path there is always a leftover to delete.
- **Toolchain and gate (C14, C15)**: Node pinned as the entry below says; `.github/workflows/ci.yml` on `pull_request` and `main` — lint, typecheck, build, then the Docker image built and health-checked; `.github/dependabot.yml` (C20 since 2026-10-21, entry below). ESLint stays the linter: it already existed, and Biome is the spec's choice for a new project only. `ci.yml` uses `actions/checkout@v7` and `actions/setup-node@v7`, the versions `release.yml` and the spec's model (`tamalou`) run on; `pages.yml` and `docker-build.yml` keep their older pins until Dependabot raises them.
- **Tests (E3)**: `npm test` on Node's own runner, in the gate (the entry below); the first suites hold the calendar's day keys and grouping, the filters and stats, the rate-limit cooldown and the sync's resume arithmetic.

- **The showcase as a public page (C17)**: canonical, link-preview tags on the 1200 × 630 card, a legal notice, one inline script (the Umami loader and the notice's switch, since 2026-10-25) and no other third-party resource — held by `tests/showcase.test.ts` (`demo-and-showcase.md`); the app itself is behind Spotify's OAuth and is not a public page. ## The `typescript` / `typescript7` devDependency pair is deliberate (2026-08-20)

TypeScript 7 ships the native (Go) compiler and no longer exposes the old JavaScript compiler API that typescript-eslint and editors still consume. Following the documented side-by-side layout (`7df4f23`):

- `"typescript": "npm:@typescript/typescript6@6.0.2"` — the compatibility package, so `node_modules/typescript` is what programmatic consumers load.
- `"typescript7": "npm:typescript@7.0.2"` — the real TS 7, invoked by path in the `typecheck` script: `node ./node_modules/typescript7/bin/tsc --noEmit`.

**How to apply**: do not "fix" either alias, and do not change `typecheck` to a bare `tsc` — that would run the v6 shim. The shim is meant to be dropped once typescript-eslint supports the TS 7 API (README points at typescript-eslint issue #10940); nobody is tracking that upstream issue, so check it before assuming it is still needed.

## The lockfile must be generated by npm 11+ (2026-08-20)

`npm ci` failed on CI because the lockfile written by npm 10 contained only the linux-x64 variants of `sharp`, `unrs-resolver` and `@next/swc`, while npm 11 (bundled with Node 24, which CI uses) validates the *full* optional-dependency set those packages declare. Fixed in `5312224` by regenerating with `npm install --package-lock-only` under npm 11, which added 52 optional platform packages and changed nothing else.

**How to apply**: regenerate the lockfile with npm 11+ (`npm install --package-lock-only`), never hand-edit it, and if your local npm is older than 11 say so rather than committing a lockfile it produced. Verify with `npm ci`.

It happened again on 2026-09-28: a local "DEV JUNK" commit (`9b8035e`) rode into a PR merge with a lockfile rewritten by an older npm — it dropped the peer-optional `@emnapi/core`, `@emnapi/runtime`, `@emnapi/wasi-threads` entries (needed by `@napi-rs/wasm-runtime`) and every `libc: ["glibc"]` field. CI's `npm ci` then failed with `Missing: @emnapi/core@2.0.0-alpha.5 from lock file`; the Docker build hides it because its `npm ci || npm install` falls back. **Remedy**: restore the last lockfile that passed, check with `npx npm@11 ci --dry-run`. **Symptom to spot in review**: a lockfile diff that only deletes `@emnapi/*` blocks and `libc` lines. The same commit also carried `next-env.d.ts` flipped to `./.next/dev/types/routes.d.ts`, which `next dev` writes and `next build` writes back to `./.next/types/…` — never commit the `dev` variant.

## `next lint` no longer exists (2026-08-20)

Next 16 removed it. ESLint is invoked directly (`npm run lint`) against the flat `eslint.config.mjs`, which spreads `eslint-config-next` and ignores `.next/`, `node_modules/`, `site/`, `public/` and `next-env.d.ts`.

## React Compiler rules are warnings on purpose (2026-08-20)

`eslint-plugin-react-hooks` v7 (pulled in by `eslint-config-next` 16) added React Compiler-backed rules that flag long-standing patterns here: mount flags, URL-state hydration, and a `Date.now()` read during render. `react-hooks/purity`, `react-hooks/set-state-in-effect` and `react-hooks/refs` are set to `warn` so lint passes while the findings stay visible. The comment in the config calls each one "a genuine cleanup" — the demotion is a deferral, not a dismissal. **How to apply**: do not silence them further, and do not promote them to errors without doing the effect rework, which is its own change.

## Node: 26 in `.nvmrc`, the floor at 22, an exact tag in Docker (2026-08-20, rev. 2026-10-24)

`.nvmrc` says `26` (24 until 2026-10-24, when the portfolio's C14 moved to 26: `.nvmrc`, both Dockerfiles and `@types/node` raised in one PR, the floor untouched), which CI (`ci.yml`, `pages.yml` through `node-version-file`) runs; `engines.node` is `>=22.18.0`: the portfolio's floor is 22 (C14) and 22.18 is the first 22 that strips TypeScript without a flag, which `npm test` relies on — Next 16 itself only needs 20.9, so the floor is a policy, not a framework constraint. Both Dockerfiles pin `node:26.12.1-alpine`: an exact tag and never a moving major, because a floating tag ships a runtime nobody tested (spotify-poller's `node:24` once pulled 24.19.0, which crashed better-sqlite3); Dependabot's `docker` block proposes each new 26.x; `@types/node` is pinned exact on 26.x like every other dev dependency here. **How to apply**: a Node-26-only API will pass CI and break a maintainer on 22 — target the floor, not what CI happens to have; raise the two Dockerfiles together, and `.nvmrc` only with a new major.

## What "verified" means here (2026-08-20, rev. 2026-10-19)

Verification is `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, plus looking at the running app (`DEMO_MODE=1 npm run dev` when you have no Spotify credentials): the tests cover the pure logic of `lib/` only, nothing that renders. `.github/workflows/ci.yml` runs those four on every pull request and on `main` and, in a second job, builds the production image and polls its `/api/health`; the Docker and Pages builds still only run `next build`, so a lint, type or test regression is caught by CI's `verify` job, not by them. Run the same commands before committing: a red job is a broken pull request.

## Tests run on Node's own runner, the TypeScript stripped by Node (2026-10-19)

`npm test` is `node --test "tests/**/*.test.ts"`: no framework, no transpiler, no new dependency — the spec's rule for a repo that had none (E3), and `tsx` is not installed here (`winnow` runs its tests through it only because it already had it). Node ≥ 22.18 / 26 strips types natively, hence the `engines` floor above. Three traps, all met on the first run:

- **A test imports its subject with the `.ts` extension** (`import … from "../lib/library.ts"`): Node's ESM loader resolves no extension. `tsconfig.json` has `allowImportingTsExtensions: true` for that, which TypeScript allows only with `noEmit` (set) and which Next's build and `tsgo` both accept; the app's own imports stay extensionless, Turbopack resolves them.
- **Only erasable syntax is stripped**: an `enum`, a parameter property or a `namespace` in a module under test is a syntax error at run time. `lib/` has none; keep it that way. `import type` is erased, so a pure module may import types from anywhere.
- **A module is loaded whole**: `lib/sync.ts` is testable although `loadJob` reads `localStorage`, because nothing touches the DOM at import time; `lib/clientCache.ts` would be, for the same reason, but its functions need IndexedDB. A helper worth testing is extracted into `lib/` as a pure function (`resumeOffset`, `appendUnique`, `activeCooldown` came out of `SyncProvider` this way) rather than tested through React.

Clocks: `mock.timers.enable({ apis: ["Date"], now })` from `node:test` holds `Date.now()` still (`tests/rateLimit.test.ts`); a time zone is pinned per file with `process.env.TZ` before any date is built, and the runner's one-process-per-file isolation keeps it there.

## Sandboxed agent environments (2026-08-20)

An ephemeral cloud session starts with no `node_modules` (they are gitignored and there is no setup script), so build/lint/typecheck need an `npm ci` first. The album-art CDN is also unreachable from at least one sandbox the maintainer used — `f58f99b` records working around it with `FAKE_COVERS=1` placeholders for the local screenshot run. Say plainly which checks you could not run rather than implying they passed.

## Dependabot follows C20 (2026-10-21)

Weekly runs with a dev-only group piled up red PRs: `react-dom`/`@types/react-dom` bumped without `react`/`@types/react` (#26, `npm ci` ERESOLVE on the peer range). **Decision**: `.github/dependabot.yml` is C20's shape — monthly, 7-day cooldown (30 for a major; security updates skip both), one `minor-and-patch` group for production and development together (never a `dependency-type` group), the `react`, `next` (with `eslint-config-next`) and `eslint` families grouped for their majors, any other major alone, three npm PRs open at most. Held majors: `@types/node` and the `node` Docker image follow `.nvmrc` (26) — a Node major is raised by hand with `.nvmrc`, CI, both Dockerfiles and `@types/node` in one PR. ESLint 10 is **not** held here, unlike regie: with `eslint-config-next` 16.4.2 it lints the repo cleanly (verified 2026-10-21, `npm run lint` under 10.13.0: 0 errors, the same 9 warnings). **How to apply**: a red Dependabot PR is never left open nor merged red — fix the repo in its own PR, or add an `ignore` with its reason here and close the PR; never push to Dependabot's branch; no auto-merge.

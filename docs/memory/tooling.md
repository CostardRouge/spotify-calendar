# Tooling — TypeScript, ESLint, npm, Node

Read before touching `package.json`, the lockfile, `tsconfig.json`, `eslint.config.mjs`, or Node versions.

## The `typescript` / `typescript7` devDependency pair is deliberate (2026-08-20)

TypeScript 7 ships the native (Go) compiler and no longer exposes the old JavaScript compiler API that typescript-eslint and editors still consume. Following the documented side-by-side layout (`7df4f23`):

- `"typescript": "npm:@typescript/typescript6@6.0.2"` — the compatibility package, so `node_modules/typescript` is what programmatic consumers load.
- `"typescript7": "npm:typescript@7.0.2"` — the real TS 7, invoked by path in the `typecheck` script: `node ./node_modules/typescript7/bin/tsc --noEmit`.

**How to apply**: do not "fix" either alias, and do not change `typecheck` to a bare `tsc` — that would run the v6 shim. The shim is meant to be dropped once typescript-eslint supports the TS 7 API (README points at typescript-eslint issue #10940); nobody is tracking that upstream issue, so check it before assuming it is still needed.

## The lockfile must be generated by npm 11+ (2026-08-20)

`npm ci` failed on CI because the lockfile written by npm 10 contained only the linux-x64 variants of `sharp`, `unrs-resolver` and `@next/swc`, while npm 11 (bundled with Node 24, which CI uses) validates the *full* optional-dependency set those packages declare. Fixed in `5312224` by regenerating with `npm install --package-lock-only` under npm 11, which added 52 optional platform packages and changed nothing else.

**How to apply**: regenerate the lockfile with npm 11+ (`npm install --package-lock-only`), never hand-edit it, and if your local npm is older than 11 say so rather than committing a lockfile it produced. Verify with `npm ci`.

## `next lint` no longer exists (2026-08-20)

Next 16 removed it. ESLint is invoked directly (`npm run lint`) against the flat `eslint.config.mjs`, which spreads `eslint-config-next` and ignores `.next/`, `node_modules/`, `site/`, `public/` and `next-env.d.ts`.

## React Compiler rules are warnings on purpose (2026-08-20)

`eslint-plugin-react-hooks` v7 (pulled in by `eslint-config-next` 16) added React Compiler-backed rules that flag long-standing patterns here: mount flags, URL-state hydration, and a `Date.now()` read during render. `react-hooks/purity`, `react-hooks/set-state-in-effect` and `react-hooks/refs` are set to `warn` so lint passes while the findings stay visible. The comment in the config calls each one "a genuine cleanup" — the demotion is a deferral, not a dismissal. **How to apply**: do not silence them further, and do not promote them to errors without doing the effect rework, which is its own change.

## Node and version floors (2026-08-20)

`engines.node` is `>=20.9.0` (Next 16's floor); the Docker images and both GitHub workflows run Node 24. **How to apply**: a Node-24-only API will pass CI and break a maintainer running 20.x locally — target the floor, not what CI happens to have.

## What "verified" means here (2026-08-20)

There is no test suite. Verification is `npm run build`, `npm run lint`, `npm run typecheck`, plus looking at the running app (`DEMO_MODE=1 npm run dev` when you have no Spotify credentials). Neither workflow gates on lint or typecheck — the Docker and Pages builds only run `next build` — so a type or lint regression reaches `main` unless you run them yourself.

## Sandboxed agent environments (2026-08-20)

An ephemeral cloud session starts with no `node_modules` (they are gitignored and there is no setup script), so build/lint/typecheck need an `npm ci` first. The album-art CDN is also unreachable from at least one sandbox the maintainer used — `f58f99b` records working around it with `FAKE_COVERS=1` placeholders for the local screenshot run. Say plainly which checks you could not run rather than implying they passed.

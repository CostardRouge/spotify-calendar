# Frontend — views, styling, state, player

Read before touching `components/`, `app/globals.css`, the views, the side rail and the filter bar, the account menu, the mini-player or URL state.

## The app is Sillon: night-first, one vivid accent, records everywhere (2026-11-27)

**Decision** (the owner found the "contact sheet" look — bone paper, serif, desaturated terracotta, hairlines — "too old, too abrupt"; the "Sillon" direction was picked from a design workshop canvas, artifact `4Cf9s6rnn43rYpmVbdGiDi`). The app is named **Sillon** (the groove of a record) everywhere a person reads it: title, manifest, home-screen name, logo, login, offline page, showcase, og card. **"Spotify" stays out of the name**: Spotify's developer terms keep their mark out of third-party app names. **Internal identifiers keep `spotify-calendar`** — the repository, `package.json`'s name, the IndexedDB name (`lib/clientCache.ts`), the cache and library folders, Sésame's app name and HMAC labels — because renaming any of them orphans saved libraries or invalidates sessions. The look: **night first** (`:root` = warm espresso `#15110e`, never blue-black; `prefers-color-scheme: light` = day on warm paper), **one accent** (`#ff6a3d` at night, `#c2410c` by day so it passes as text on paper), rounded surfaces (16px cells, pill buttons) instead of hairlines, no paper grain; album art still carries every other colour. Type: **Unbounded** (round, wide; dates, numbers, headings) + **Inter** (everything else), self-hosted as woff2 in `app/fonts/` (OFL files beside them) through `next/font/local` — never a font CDN, so the CSP's `font-src 'self'` holds. **How to apply**: never hard-code a colour in a component — add or reuse a token, with a value in *both* palettes; a second saturated accent works against the system, ask first. The showcase copies the palette but loads no font (system sans at 800 for headings).

**What Sillon added on top of the restyle** (logic in `lib/`, tested): the Year view is a **record** (`lib/disc.ts`: a groove per month, January at the label, a full lap per month, a dot per day sized by count and capped below the groove gap; the month list beside it is the keyboard path, dots are too small); **"Drop the needle"** (`randomDay`, every day with saves weighs the same, within the filters → day view); **"A year ago"** in the day view (`yearAgo`: same day last year, else nearest within ±3 days, earlier on a tie; 29 Feb → 28 Feb); a **horizontal swipe** on the day view turns the day (>60px and 1.5× more horizontal than vertical, so scrolling never skips); month cells **fan** up to three covers (two on a phone) through `--fan-x/--fan-r` custom properties, with `×N` shown only when N > 1; the mini-player's cover is a record turning at 33⅓ rpm only while `isPlaying`. Everything that moves stops under `prefers-reduced-motion`.

**Traps met**: Chromium's "iPhone 13" profile is 390×**664** (Safari's bars), so month rows crushed to ~39px and covers hid the day numbers — rows have `minmax(52px, 1fr)` on a phone and the grid scrolls; the phone header is one line (logo, needle as an icon, account avatar) and the calendar head wraps to two. Between 769 and 1080px the side rail keeps its icons only (labels kept for screen readers).

## State lives in the URL, restored once on mount (2026-08-20, rev. 2026-11-27)

`CalendarApp` reads the query string once on mount (filters, anchor date), sets `urlReady`, and only then starts mirroring state back out. The view itself comes from the path (see `architecture.md`). An explicit `?d=` date beats the automatic jump-to-latest. The folded filter column (`panel=0`, its head script and the `data-panel-collapsed` → `app-ready` handoff) is gone with the column itself (2026-11-27); `searchToState` ignores `panel` so old links still open. **Device choices are not URL state**: theme, month layout and wall order live in localStorage (`lib/prefs.ts`, next section) — a shared link opens in the reader's own theme and layout.

## Filters are pure functions over the whole library (2026-08-20)

`lib/library.ts` holds `albumPasses` / `filterAlbums` / `groupByDay` / `artistIndex` as pure functions; the components only ever call them. Filtering happens client-side over the full loaded library, which is why the whole library is synced up front rather than queried per view. The `kinds` filter can never be emptied — unchecking the last one falls back to showing both, because an empty calendar with no explanation reads as a bug.

## Large libraries need the rendering guards (2026-08-20)

`ListView` renders progressively behind an `IntersectionObserver`; grid and card elements use `content-visibility: auto` with `contain-intrinsic-size`; every cover uses `loading="lazy"` and `decoding="async"` (`afeca9a`). With thousands of albums these are what keep scrolling usable. **How to apply**: a new view showing many covers needs the same treatment; removing `contain-intrinsic-size` alongside `content-visibility` reintroduces scrollbar jumping.

## The mini-player is a Spotify Connect remote, not a player (2026-08-20)

Playback is controlled through the user's *active Spotify device*; the app never plays audio itself, which is why the control endpoints need Premium and surface 403 as "premium_required" (see `spotify-api.md`). The queue panel and the device picker are mutually exclusive popovers — opening one closes the other, deliberately, so they never stack.

## PWA and the icon set (2026-08-20, rev. 2026-10-19)

`public/manifest.webmanifest` ships `standalone` display (the state lives on the server and in a per-user IndexedDB snapshot the app rebuilds from a sync, so a standalone launch loses nothing), `any` + `maskable` icons at 192/512, `start_url: "./?source=pwa"`, and `background_color` / `theme_color` both the night `--bg` (`#15110e`, since 2026-11-27). The home-screen name is `Sillon`. **How to apply**: changing the night palette's `--bg` means changing the manifest, `app/layout.tsx`'s `themeColor` and `public/offline.html` to match, or the splash screen no longer matches the app.

**The icon set is the portfolio's (C11, 2026-10-19; redrawn as a record for Sillon 2026-11-27)**: `public/icons/` holds three SVG sources — `icon.svg` the rounded tile (the tab, the manifest's `any` pair), `icon-apple.svg` and `icon-maskable.svg` full bleed, the latter with the drawing at 70 % so it stays inside the launcher's 80 % safe zone — and the PNGs `scripts/gen-icons.mjs` rasterises from them with `sharp` (it also writes `public/favicon.ico`, the 16 + 32 PNGs in an ICO container) (an optional dependency of Next already in `node_modules`, never a dependency of this project; `npm i --no-save sharp` if it ever goes). `app/layout.tsx` declares them through `metadata.icons` (the SVG, `favicon-16/32`, the touch icon, `favicon.ico` kept at the root because browsers ask for it blindly) and `metadata.manifest`; the manifest's paths are **relative**, so the same file would resolve under a base path. **Why**: iOS builds a home-screen icon from `apple-touch-icon` alone, a PNG, square and opaque — the previous one carried an alpha channel, which Apple's mask composites onto black — and the raster favicons were missing for the browsers that still prefer one to the SVG. **How to apply**: edit a source, run the generator, commit the PNGs with it; `tests/icons.test.ts` holds the sizes, the touch icon's missing alpha and the manifest's relative paths, so a forgotten regeneration fails the gate. The showcase on GitHub Pages reuses the same files (`pages.yml` copies `public/icons`, `demo-and-showcase.md`).

## Phone layout and the installed app (2026-11-26)

**Decision** (the owner's report from the sibling spotify-poller PWA on an iPhone: tab bar cut by the corners and home indicator, content off the right edge; same work done here, measured first). At ≤768px the side rail gives way to a header (logo, needle, account avatar) and the tab bar; the filter bar becomes one row scrolled sideways (`overflow-x`), and its menus and the account menu become **sheets from the bottom** over a scrim (`position: fixed`, so the row's overflow does not clip them). (The 2026-11-26 filter drawer went with the filter column, 2026-11-27.) `.app` is `100dvh` (100vh put the tab bar under iOS Safari's toolbar) and pads the top and sides with `env(safe-area-inset-*)`; the tab bar is **in the flow**, not fixed, and pads its own bottom with `max(6px, inset)`; the mini-player is fixed above it. None of the insets worked before: `viewport.viewportFit: "cover"` (`app/layout.tsx`) is what makes them non-zero. Fields are 16px under `(pointer: coarse)` (iOS zooms into smaller ones). `appleWebApp.statusBarStyle` stays `"default"` — `black-translucent` puts white text over the light paper. No tables exist, so spotify-poller's records reflow had nothing to apply to. **How to apply**: measure with Playwright at the iPhone 13 profile on a built, demo-mode app (`DEMO_MODE=1 next start`, click "Start sync" first or every view is the empty state): `documentElement.scrollWidth` must equal the viewport, and list any element whose right edge passes it. Chromium reports every safe-area inset as 0, so the iPhone result is only known once the owner re-adds the app to a home screen (MEMORY.md, open items).

**The service worker caches only `offline.html`** (`public/sw.js`, registered by `components/ServiceWorker.tsx` in production only; GET navigations, network first, navigation preload, `VERSION` bumped when the page changes). Caching the view shells would let the calendar open offline from the IndexedDB snapshot — a real gain, rejected for now because every deploy renames `_next/static` chunks and a stale shell against a new server is invisible from a phone. Revisit only with a versioned shell + chunk cache cleared on activate. Manifest shortcuts: Month, Week, Year, Stats (four is Android's limit), relative URLs; `tests/pwa.test.ts` holds them to `app/[view]/page.tsx`'s `VIEWS`.

## Iteration 3: side rail, filter bar, the wall, the account menu, the theme (2026-11-27)

**Decision** (the owner, on the design canvas `4Cf9s6rnn43rYpmVbdGiDi`, page "Itération 3 — synthèse", which is the reference): covers were "too small to enjoy the artwork", the stats tiles cut names, there was no theme switch, and the top bar mixed log-out, sync, count and version. Chosen: **views in a side rail** on a computer (tab bar kept on a phone), **filters always in view** as a bar above every view (All/Albums/Songs, search, Artist and Released menus — the long lists cannot stay open, hence menus), the **account at the rail's foot** (menu opening upward; avatar + bottom sheet on a phone) holding the count, sync state and action, `/sync` link, theme, GitHub, what's new + version, log out. **Month = Wall by default** ("elegant and new", though the owner feared some readers get lost): an orange-numbered tile per day with saves, then its covers full size; days run **1 → 31 by default** ("more classic"), a sort button beside the layout switch flips it; a **one-time explanation** (`slc_wall_hint_seen`) says what the wall is and points to Grid. **Wall | Grid** replaced the old "Covers / Fan" idea: the grid now fills each cell with the day's first cover (the fan and `Covers.tsx` are gone), a dark pill keeps the number readable over any art, `×N` only past one, the next covers in a corner, and a hover card (pointer devices only, opened after a 0.3s animation delay) shows the whole day; the grid has 5 or 6 rows as the month needs. Week = a big lead cover per day. Stats = **bento** (`grid-template-areas` at 6 / 4 / 2 columns) with no genre tile (Spotify gives none — `spotify-api.md`); "Days with saves" and "Oldest record" (`computeStats`: `activeDays`, `oldest`, `topArtists` with each artist's latest cover). Year = the calendar's month (or the one hovered) drawn as **covers on its groove**, every other dot a quiet `--faint` — the all-orange disc read as duotone. **No underlined links** anywhere (the owner found them noisy).

**How it is built**: `lib/prefs.ts` (pure parsing + storage inside functions, tested) holds theme `auto|night|day`, month layout `wall|grid`, wall order `asc|desc` under `slc_*` keys — **per device, not per Spotify account**; `components/usePrefs.ts` is a `useSyncExternalStore` store so the two mounted account menus (rail and phone header, one visible) never disagree. The theme: `THEME_BOOT_SCRIPT` inlined in `<head>` sets `data-theme` before the first paint; `globals.css` has the day palette twice — under `prefers-color-scheme: light` with `:root:not([data-theme="night"])`, and under `:root[data-theme="day"]`; `applyTheme` also rewrites the two `theme-color` metas. **Keep both day blocks identical** when touching a token. The account name comes from an `sp_name` httpOnly cookie written at login from the profile the callback already fetches; `/api/me` returns it with the id and **spends no Spotify call** (older sessions show "Your account" until their next login).

**Traps met**: an SVG `fill` *attribute* loses to a stylesheet `fill` rule — the cover patterns on the disc needed `style={{ fill }}`. The wall flows days and covers in one grid through `.wall-day { display: contents }`; on a phone the date tile spans the row (`grid-column: 1 / -1`) to become a header line. The grid's hover card needs the cell's `overflow` visible (the art sits in its own clipped `.day-art`), and opens left on the last three columns and upward on the last rows, or `.view-body` clips it. Hidden lazy images never load, so the showcase script's "images settled" check skips images out of view. A demo server keeps the synced demo library server-side: a second local capture run opens straight on it, with no "Start sync" button (`startSync` in the script handles both).

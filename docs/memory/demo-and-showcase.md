# Demo mode & the GitHub Pages showcase

Read before touching `DEMO_MODE`, `lib/demo.ts`, `lib/demo-library.json`, `showcase/`, `scripts/`, or `.github/workflows/pages.yml`.

## Demo mode is a product feature, not a test fixture (2026-08-20)

`DEMO_MODE=1` makes every API route serve a fixture library and require no authentication — including `/api/auth/login`, which redirects straight to `/month` so the "Connect" button works. It exists for two reasons at once (`e32cd43`): anyone can run `DEMO_MODE=1 npm run dev` and poke at the UI without creating a Spotify app, and the Pages workflow can boot the app headlessly to take **real** screenshots of the real UI rather than mock-ups.

**How to apply**: a new route that calls Spotify must handle `isDemo()` too, or it 401s in the showcase build and the screenshot shows an error state. `demoPage()` and `demoGenres()` return the same shapes as the Spotify-backed helpers, so the demo branch stays a one-liner at the top of the route.

## The fixture library is real releases with synthetic dates (2026-08-20)

`lib/demo-library.json` is generated by `node scripts/build-demo-library.mjs` and holds real albums, tracks, artists and cover-art URLs; only the save-dates are invented, so the calendar looks plausible. Items ship pre-genred, which is why `demoGenres()` resolves from the fixtures instead of calling anything. **How to apply**: edit the seed lists in the script and regenerate — do not hand-edit the JSON.

## Screenshots are captured against a running app (2026-08-20)

`.github/workflows/pages.yml` on every push to `main`: `npm ci` → install Playwright chromium → `npm run build` → start with `DEMO_MODE=1` → poll `/api/health` until it answers → `node scripts/showcase-screenshots.mjs site/screenshots` → copy `showcase/index.html`, `public/favicon.svg` and `public/og-image.png` into `site/` → deploy.

Consequences worth knowing:

- `site/` is **generated and gitignored**. Edit `showcase/index.html` and the script; never `site/`.
- Screenshots regenerate on every deploy, so anything visible in the app (titles, layout) propagates to the showcase automatically — and a stale name in the app shows up in the screenshots, which is exactly how `f58f99b` was noticed.
- The script waits for every visible `<img>` to settle, then pauses 400 ms for lazy decodes, and captures anyway on timeout rather than failing the build.
- `FAKE_COVERS=1` replaces the album-art CDN with generated placeholders for offline or sandboxed local runs. CI leaves it unset and loads real art. Never commit screenshots taken with it.
- One-time repo setup, not reproducible from code: **Settings → Pages → Source: "GitHub Actions"**.
